Cards as data — capability blocks the sim interprets

Each card's rules are captured from its text as a front and a back effect block (game/reef_cards.gamespec.md). A generic interpreter (mechanisms/card_effects.py) reads them and works out the turn — no per-card logic in the sim. This is the same Reef Gardens turn 1, now driven entirely by the data.

What a capability block looks like

Lead Ecologist — a role passive (an Oxygen icon)

card_effects:
  id: reef_gardens_3_lead_ecologist
  front: { role: true, hidden: true }
  back:
    disposition: to_player_hand
    passive:
      - { provides_icon: { icon: oxygen, amount: 1 } }

Systems Ecologist — a role passive that is an ACTION

  back:
    passive:
      - { action: { id: cultivator,
            change_track: { track: population,
              target: { type: flora, at: location, choose: player }, delta: 1 } } }

Shallowwater Filterweed — a conditional icon + Pop-banded upkeep

  front:
    provides_icon:
      - { icon: oxygen, amount: 1, when: { self_pop_ge: 3 } }
    upkeep:
      bands:
        - { pop: 1,   do: [ { change_track: { track: population, target: self, delta: 1 } } ] }
        - { pop: "2-4", do: [ { change_track: { track: population, target: self, delta: 2 } } ] }
  back:
    on_reveal:
      - { disposition: play_at_location }
      - { set_track: { track: population, value: 2 } }

Spawning Ground — a unanimous dilemma, each option a real effect

  front:
    dilemma:
      choose: unanimous
      options:
        - { id: tag_monitor, label: "Tag & Monitor",
            do: [ { provides_icon: { icon: knowledge, amount: 1 } }, { tuck: { under: outpost } } ] }
        - { id: protect, label: "Protect",
            do: [ { change_track: { track: population, target: card.…filterweed, delta: 2 } },
                  { change_track: { track: population, target: card.…grazers, delta: 2 } } ] }

Reef Ecologist's Notes — a CONDITIONAL gain

  back:
    on_reveal: [ { disposition: set_beside_deck } ]
    conditional_gain:
      - { to: player_hand, when: { location_cards_pop_ge: { pop: 4, count: 2 } } }

Reef Caverns — the expedition gate (presence test)

  back:
    gate:
      requires: { oxygen: 2, knowledge: 2 }
      sourced_from: [hand, location]

Beyond the gate — the caverns, exercised

The same interpreter drives cards 16–21. Forcing the gate open (a labelled hypothetical, not a legal move on this tally) runs the deep's own upkeep verbs: cross-card conditions (card_track_ge), an apex predator that consumes Prey population, a mineral that produce_resources Materials at Abundance 2+, and an Event that remove_selfs when it finds nothing to act on. Resources produced: {'materials': 1}.

A rule the encoding surfaced. The Snapper is an apex predator that eats Prey; the surface Grazers eat Fauna. Run together, the Grazers' consume_population: {from: {type: fauna}} can eat the Snapper — predator and prey reversed. That is a concrete, testable content question the executable layer made visible, exactly what it is for. It's flagged in the block's DESIGN NOTE, not silently resolved.

gsx validates the blocks themselves

Because the rules are data, gsx checks them like any contract: PASS — 18 capability blocks; every verb, icon, track and card reference resolves. Unencoded prose is not an error — it is an honest, tracked status: unresolved marker (INFO), so the gaps are counted, not hidden:

unresolvedcard reef_gardens_13_reef_ecologist_s_notes: Take 1 Reef Fauna/Flora into hand
unresolvedcard reef_gardens_19_drowned_survey_cache: Trash: ask Control any question (adjudicated)
unresolvedcard reef_gardens_21_bioluminescent_pollination: A Flora you move gains +1 Pop on arrival if at Depth 3+ (movement/Depth not modelled)

The effect-verb vocabulary (closed set)

dispositionwhere a turned card goes (hand / play / set_aside / beside_deck / resolve / discard)
provides_icon{icon, amount, when?} — a presence icon (not consumed), optionally conditional
set_track / change_trackinitialise or adjust a card track (population, abundance, …)
passivepersistent effect on a role/card: an icon, or an {action: …}
reveal_cards / each_player_choosessetup: reveal cards, each player keeps one (assigns roles)
conditional_gaingain a set-aside card when a condition holds (e.g. two cards at 4+ Pop)
dilemma{choose: unanimous, options: [{id, label, do:[effects]}]}
choose_onepick one of several upkeep effects
gate{requires: {icon: n}, sourced_from, on_meet} — the expedition gate
tuck / instruction / narrativetuck under a card; read-aloud; flavour (no mechanic)
status: unresolvedan honest, tracked marker for prose not yet encoded

Adding a card is now authoring a block, not editing the sim. Encoding a prose effect means adding its verb here (e.g. the Grazers consume_population / else op, or the Outpost Rations) — and gsx validates that every verb, icon and reference resolves: a new verb the interpreter doesn't know fails L6, so the data and the interpreter can't drift apart.
